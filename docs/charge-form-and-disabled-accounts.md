# Departure Charge Form and disabled employee accounts

Charge Form opens from Departure, immediately before Counter / Gate Default. All linked MU operations employees can fill and print it. Shared base-price changes require the same default Lead-or-higher permission as Departure defaults; ordinary employee overrides cannot grant price administration. SQLite stores revisions and audited price changes.

The reference is [the supplied worksheet](https://docs.google.com/spreadsheets/d/1VDIRN77cKZMQPXQ1ZLY-8lp8VI44tpFD5oU1Q9YAzYs/edit?gid=550963234#gid=550963234). `charge-form-model.js` records its CNY bases and fixed USD upgrades. Converted USD amounts use base CNY multiplied by the unrounded exchange rate, displayed as whole dollars to match the worksheet. The exchange rate comes from `getLatestFlightLog()` and the existing `extractFscExchangeRate()` parser for the XS FSC `RATE BSR 1CNY = … USD` output. An unavailable log leaves the rate blank. The first XS FSC result is stored in SQLite for the current Los Angeles date. Manual rate edits save on leaving the field and become the shared rate for that day. Reopening or restarting reuses that rate; the next local date starts a new lookup. The form renders immediately while the first log lookup runs separately. Wording edits apply only to the open form. Titles, column headings, item names, notices and acknowledgment text can be edited directly. Price cells can also be edited directly by Lead+ for the open copy; Edit prices → Save prices explicitly publishes shared base-price changes. Ordinary employees cannot edit price cells. The supplied airline logo is preserved as an asset and rendered in monochrome. Isolated print documents retain entered fields and checks on one portrait A4 or Letter page in the verified standard layout.

The HR Permission panel appends Disable account after the permission catalog, so future ordinary permissions remain above it. Changes apply immediately through a separate, management-scoped endpoint. Self-disable and owner-disable are rejected. Firebase account updates use `disableUser` and `validSince`; all linked identities and matching login-email identities are included.

Local access is blocked before contacting Firebase. A synchronization failure leaves the employee disabled with a visible retry action. Enabling completes only after successful synchronization and requires a fresh sign-in. Access changes are audited. Disabling closes tracked authenticated streams, suppresses pending push jobs and disables device tokens; the shared sender also rechecks account status immediately before delivery. No attempt is made to retract already delivered notifications.

`employees.get()` supplies active operational people; `getAll()` retains the management view. Ordinary saves preserve hidden disabled records and cannot overwrite account-status fields. HR retains disabled profiles for management and re-enabling. Existing stored assignments/history are retained, while current Briefing responses omit disabled names. Operational Schedule rows, rosters and name selectors consume the active store view. Reporting-manager choices exclude disabled employees.

HAS-PBB avatar/name navigation follows the currently selected account: LAX/MU opens Flights; other scopes open Home. The separate caret still opens password, notification and logout controls.

Validation includes permission/revision checks, multi-identity disable and re-enable, Firebase failure/retry, old-session rejection, push suppression, roster/assignment filtering, responsive HR and PBB flows, exchange-rate overrides and one-page print exports. Tests use fake identities and mock Firebase updates; no production employee was disabled.

Price fields retain their original CNY bases when focused without an edit. The price editor remains available after saving or closing/reopening. Upgrade item cells are centered, the seat/purchase-ticket rows omit their RMK captions, and Baggage labels its existing CBS shortcut Departure Rush Bag.
