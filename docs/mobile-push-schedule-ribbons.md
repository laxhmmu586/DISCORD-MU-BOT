# Phone-only push and mobile Schedule ribbon stability

Push notifications target every enabled mobile subscription for the recipient, independent of open desktop tabs or page visibility. The server filters recipients at dispatch, retires old desktop registrations at startup and declines new desktop registrations without touching other devices. Mobile registrations include an explicit iOS Home Screen or Android platform; legacy phone user agents remain supported. The desktop notification switch explains that push is delivered to the phone only and does not request notification permission.

Production inspection before this change found 15 enabled iOS subscriptions, one disabled iOS subscription and one enabled desktop subscription. The account with the desktop also retained two enabled iOS registrations. All 59 recorded device deliveries were acknowledged by FCM without recorded errors. This does not prove that a phone displayed every notification, and did not establish that the desktop was suppressing delivery. The custom service worker already displays accepted push events without inspecting foreground clients; that behavior is retained and tested.

For manager mobile Schedule, date ribbons now stay inside their sticky date cells with reserved header space. They do not use the measured sibling overlay, so compositor scrolling moves them with the dates. Desktop and employee renderers remain unchanged. Mobile scrolling no longer synchronizes with hidden desktop Coverage grids, which could feed a stale/clamped offset back into the manager view.

Validation: 96 focused notification, permission, routing, Schedule, roster, grid and summary tests pass. Browser inspection with synthetic data at 375px and 390px verifies native manager labels, vertical/horizontal scrolling, stable post-scroll offsets, no page overflow and the unchanged employee renderer. The measured label-to-cell drift over both scroll directions was below 0.001 CSS pixels. Real iPhone OS notification display and iPhone compositor behavior still require device confirmation; no test employee notification was sent.
