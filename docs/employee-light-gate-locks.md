# Light employee workspace, PBB dialog and gate locks

Admin, Info, Request, Read & Sign and Attendance use the same white surfaces, Hallmark branding, pale borders and blue actions as Profile. The attendance request form also has a light stylesheet. Existing navigation, permissions, approval flows and signatures remain intact. PBB settings now open an accessible dialog with five fields; Cancel/Escape discard the draft, Apply updates the employee row, and the existing employee-list Save persists changes. The row does not grow while the dialog is open.

HAS stores confirmed gates in SQLite per station/account/flight. Confirmation fixes `confirmedAt` and `expiresAt` two hours apart; confirming the same active gate cannot extend its deadline. A different gate requires clearing the active hold first. The orange Clear gate number button replaces the visible Confirm action and the gate input becomes read-only. Holds survive reload and backend restart. Server time anchors client expiry timers, context refresh reflects another operator's changes, and expired holds are removed on access. Clearing a hold leaves checklist audit data intact; confirming a different gate and opening a bridge uses the existing scoped checklist-reset behavior. A local preference stores only the most recently selected flight for the employee's station/account.

The serviceable question uses the user-supplied complete photograph, optimized to `assets/pbb/has-serviceable-user-v1.webp` without cropping or semantic edits.

Read & Sign excludes employees without a valid personal or company email from new rosters and notification jobs. Existing memo views and aggregate signature counts also exclude those accounts based on current employee addresses. Stored memo rosters and signatures remain intact as audit data. A company-only email is sufficient; login ID alone is not a notification email.
